# AgroFarm Constitution

## Core Principles

### I. Мінімальна складність
Архітектурні та програмні рішення MUST бути найпростішими з тих, що повністю
задовольняють вимоги. Необґрунтовані абстракції та функціональність поза межами
поточного навчального завдання MUST NOT додаватися. Це зберігає код зрозумілим
для навчання.

### II. Єдина відповідальність класу
Кожен клас MUST мати одну чітко визначену відповідальність і змінюватися з однієї
основної причини відповідно до принципу SRP. Клас, що поєднує незалежні обов'язки,
MUST бути розділений, коли це необхідно для виконання вимог.

### III. Заміщення зовнішніх операцій повідомленнями
Методи, що представляють зовнішні або реальні операції, MUST виводити в консоль
повідомлення про заплановану дію замість виконання цієї операції. Повідомлення
MUST давати зрозуміти, яку дію представляє метод. Це дає змогу демонструвати
поведінку системи без зовнішніх побічних ефектів.

### IV. Командний рядок без зовнішніх залежностей
Компіляція та запуск застосунку MUST бути можливими з командного рядка. На
поточному етапі застосунок MUST NOT залежати від зовнішніх сервісів або баз даних.
Інструкції, потрібні для компіляції та запуску, MUST бути доступні в специфікації
проєкту.

### V. Явне впровадження залежностей
Залежності MUST впроваджуватися через конструктори або setter-методи. Статичні
методи MUST NOT використовуватися для впровадження залежностей. Явне передавання
залежностей робить зв'язки між класами зрозумілими.

### VI. Розділення мов програмного коду та пояснень
Назви класів, методів, атрибутів та інших програмних елементів MUST бути
англійською мовою. Коментарі до коду та пояснення MUST бути українською мовою.
Це правило забезпечує послідовність іменування коду й доступність навчальних
матеріалів.

### VII. Текстові UML-діаграми в каталозі docs
UML-діаграми MUST зберігатися в каталозі `docs` у текстовому форматі. Діаграми
MUST відповідати актуальній структурі або поведінці, яку вони описують.

### VIII. Специфікація українською мовою
Специфікація проєкту MUST вестися українською мовою. Зміни до вимог і рішень
проєкту MUST відображатися в специфікації українською мовою.

## Implementation Constraints

Застосунок моделює предметну область «Агропідприємство» як навчальний Java-проєкт.
Усі рішення MUST відповідати наведеним принципам; будь-яке розширення поточних
обмежень потребує внесення змін до цієї Конституції.

## Documentation and Development Workflow

Розробники MUST перевіряти, що зміни відповідають специфікації та цій Конституції.
Під час змін структури системи пов'язані текстові UML-діаграми MUST оновлюватися.
Пояснення в документації MUST бути українською мовою, а програмні ідентифікатори —
англійською.

## Governance

Ця Конституція є обов'язковою для проєктування, реалізації та перевірки змін.
Поправки MUST бути внесені до цього документа та переглянуті разом із відповідними
змінами проєкту. Відхилення від принципу MUST бути явно обґрунтоване в специфікації
та затверджене під час перегляду змін.

Версія Конституції MUST відповідати семантичному версіонуванню: MAJOR — несумісна
зміна принципів або вимог; MINOR — додавання принципу чи суттєве розширення
вимог; PATCH — уточнення формулювань без зміни нормативного змісту.
Відповідність Конституції MUST перевірятися під час перегляду змін, зокрема
щодо відповідальностей класів, способу впровадження залежностей, консольної
поведінки та актуальності документації.
