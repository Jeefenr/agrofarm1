# Збереження даних — Checklist вимог

**Purpose**: Оцінити повноту, ясність і узгодженість вимог щодо SQLite, Guice та статичного звіту.
**Created**: 2026-11-13
**Feature**: [spec.md](../spec.md)

**Note**: Цей checklist згенеровано на основі специфікації та артефактів дизайну функції.
**Review Ownership**: Це checklist якості вимог, власником якого є рецензент. Позначайте пункт `[x]` лише якщо рецензент визнав відповідний критерій якості вимог задоволеним.
**Marker Semantics**: `[x]` означає, що критерій перевірено і вимоги відповідають йому; це не означає завершення реалізації.

## Повнота вимог

- [ ] CHK001 Чи однозначно визначено повний набір атрибутів запису та їхній зв’язок із полем у вимогах і контракті? [Повнота, Узгодженість, Spec §FR-004, §FR-009]
- [ ] CHK002 Чи визначено правила стабільності, унікальності та призначення ідентифікатора операції між запусками? [Gap, Неоднозначність, Spec §FR-004, §FR-014]
- [ ] CHK003 Чи визначено допустимі значення та обов’язковість типу, стану й ідентифікаторів перед збереженням? [Gap, Plan §Перевірки даних]
- [ ] CHK004 Чи достатньо чітко описано створення файлової бази під час першого запуску та після видалення `target`? [Повнота, Spec §FR-004, §Граничні випадки]

## Ясність і вимірюваність

- [ ] CHK005 Чи узгоджено, чи звіт має показувати лише ID пов’язаного поля, чи й його назву? [Неоднозначність, Spec §FR-004, §FR-009; Contract §Контракт HTML-звіту]
- [ ] CHK006 Чи визначено, що саме вважається «помітним попередженням» у звіті про невдалі записи? [Неоднозначність, Spec §FR-016; Contract §Контракт HTML-звіту]
- [ ] CHK007 Чи можна об’єктивно відрізнити помилки створення каталогу, збереження та читання за вимогами до повідомлень і результату запуску? [Ясність, Spec §FR-013, §FR-015, §FR-017]
- [ ] CHK008 Чи визначено, чи має помилка читання або створення каталогу впливати на код завершення процесу, окрім заборони повідомляти про успіх? [Gap, Ясність, Spec §FR-013, §FR-017]
- [ ] CHK009 Чи достатньо точно визначено, які символи й контексти HTML потрібно екранувати, щоб критерій «відображати як текст» був вимірюваним? [Вимірюваність, Spec §FR-009; Plan §Підхід до дизайну]

## Узгодженість вимог та критеріїв приймання

- [ ] CHK010 Чи розмежовано незмінність наявних консольних повідомлень і нові повідомлення про помилки, щоб ці вимоги не суперечили одна одній? [Узгодженість, Spec §FR-001, §FR-013, §FR-015, §FR-017]
- [ ] CHK011 Чи критерії успіху охоплюють не лише наявність записів у звіті, а й правильність кожного відображеного атрибута та зв’язку з полем? [Критерії приймання, Spec §FR-008, §FR-009, §SC-002]
- [ ] CHK012 Чи визначено, як зіставляти вимогу «усі записи» з даними попередніх запусків і оновленнями поточного запуску? [Ясність, Узгодженість, Spec §FR-008, §FR-014]

## Покриття сценаріїв

- [ ] CHK013 Чи повністю визначено основний сценарій від збереження призначених операцій до побудови звіту з актуальних даних? [Покриття, Spec §FR-004, §FR-008]
- [ ] CHK014 Чи визначено результат повторного запуску для незмінних ID, змінених атрибутів та нових операцій без дублікатів? [Покриття, Spec §FR-014]
- [ ] CHK015 Чи повністю визначено поведінку після часткової помилки запису, зокрема продовження інших записів і вміст звіту? [Покриття, Винятковий сценарій, Spec §FR-015, §FR-016]
- [ ] CHK016 Чи визначено окремий результат невдалого читання після спроб збереження, включно з відсутністю успішного звіту? [Покриття, Винятковий сценарій, Spec §FR-013]
- [ ] CHK017 Чи визначені вимоги до порожнього результату як для відсутності призначених операцій, так і для порожньої бази? [Покриття, Граничний випадок, Spec §FR-009; Contract §Контракт HTML-звіту]

## Граничні випадки та відновлення

- [ ] CHK018 Чи визначено очікуваний результат, якщо створення `target` неможливе, і чи узгоджений він із поведінкою при помилках БД? [Покриття, Винятковий сценарій, Spec §FR-013, §FR-017]
- [ ] CHK019 Чи чітко повідомлено користувачу про те, що очищення або видалення `target` видаляє також збережені дані, а наступний запуск починає з нової БД? [Припущення, Spec §Граничні випадки; Contract §Контракт збереження]
- [ ] CHK020 Чи визначено очікувану поведінку для некоректних або порожніх атрибутів запису, якщо такі значення можуть виникати у сценаріях? [Gap, Граничний випадок, Plan §Перевірки даних]

- [ ] CHK022 Чи узгоджено мінімальні версії Java та Maven між вимогами запуску й технічним планом, щоб інструкції були відтворюваними? [Узгодженість, Spec §Історія користувача 3; Plan §Технічний контекст]
