# Завдання: Збереження даних агропідприємства через SQLite та Guice

**Вхідні документи**: `specs/004-sqlite-guice-storage/`

**Передумови**: `plan.md`, `spec.md`, `research.md`, `data-model.md`, `contracts/`

**Тестування**: План і quickstart вимагають автоматизованих перевірок через `mvn test`; окремі тестові завдання включені до відповідних історій.

**Організація**: Завдання згруповані за історіями користувачів для незалежного впровадження та перевірки.

## Формат завдань

- **[US1]**, **[US2]**, **[US3]**: історія користувача зі специфікації.
- Кожне завдання має шлях до файлу, який потрібно створити або змінити.

## Фаза 3: Історія користувача 1 — Збереження технічних операцій поля (Пріоритет: P1, MVP)

**Мета**: зберігати кожну призначену полю операцію у файловій SQLite-базі, оновлювати запис за стабільним ID та явно повідомляти про помилки.

**Незалежна перевірка**: виконати сценарій збереження й перевірити в `target/agrofarm.db`, що для кожної операції збережені ID операції, тип, стан та ID поля; повторити запуск із тим самим ID і переконатися, що рядок оновився без дубліката.

- [ ] T005 [P] [US1] Додати тести в `src/test/java/agrofarm/FieldPersistenceTest.java` для конструкторного впровадження `TechOperationStore`, передавання ID саме поля-власника до запису та явного результату невдалого збереження.

**Контрольна точка**: операції зберігаються та читаються незалежно від звіту; повторний запуск із тими самими ID не створює дублікатів.

## Стратегія впровадження

### MVP — лише історія користувача 1

1. Виконати фазу 1: налаштувати Maven і залежності.
2. Виконати фазу 2: визначити `OperationRecord` і `TechOperationStore`.
3. Виконати фазу 3: впровадити стабільні ID, SQLite-сервіс, Guice та збереження через `Field`.
4. Перевірити автоматизовані тести й незалежно підтвердити запис, читання та UPSERT у `target/agrofarm.db`.

### Поступове постачання

1. Підготовка й контракти → придатна до розробки Maven-основа.
2. Історія 1 → збереження операцій та оновлення за стабільним ID.
3. Історія 2 → HTML-звіт із фактичного стану SQLite.
4. Історія 3 → відтворювані команди запуску й актуальні UML-діаграми.
5. Виконати наскрізні кроки з quickstart та звірити документацію.

## Примітки

- Завдання з `[P]` змінюють різні файли й не залежать від незавершених завдань.
- Мітка історії відповідає історії користувача зі `spec.md`.
- SQL для таблиці, UPSERT і читання має бути лише в `SQLiteTechOperationStore`.
- Не змінювати наявний порядок сценаріїв і тексти чинних україномовних повідомлень.
