# Дослідження: Збереження даних агропідприємства через SQLite та Guice

## Рішення: Java 21 через Maven Compiler Plugin

**Рішення**: Використовувати JDK 21 як цільову версію компіляції Maven через параметр `release=21`, а не окремо виставляти лише `source` і `target`.

**Обґрунтування**: Опція `--release` перевіряє мовну версію, формат байткоду та доступні API цільового релізу. Maven документує передавання цієї опції через властивість `maven.compiler.release`.

**Альтернативи**: `source`/`target` не забезпечують такої ж перевірки доступності API; використання новішої версії API може залишити несумісний код.

**Джерела**: [Maven: Targeting a Java Version](https://maven.apache.org/guides/mini/guide-java-target.html).

## Рішення: Maven стандартна структура та автоматичні тести

**Рішення**: Зберегти `src/main/java` і `src/test/java`, додати `pom.xml`, закріпити сумісні версії плагінів і залежностей. Використати JUnit Jupiter лише для тестового коду, щоб `mvn test` автоматично перевіряв наявні сценарії та нову поведінку.

**Обґрунтування**: Стандартні каталоги розпізнаються Maven без додаткового налаштування; існуюча структура репозиторію вже їм відповідає. Тестова залежність не потрапляє до runtime-залежностей застосунку.

**Альтернативи**: Зберегти власний тестовий `main` без інтеграції в Maven — це вимагало б окремого ручного запуску та не перевіряло б поведінку звичайним `mvn test`. Змінювати директорії чи створювати багатомодульну збірку немає потреби.

**Джерела**: [Maven Standard Directory Layout](https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout.html).

## Рішення: конструкторна ін'єкція та модуль Guice

**Рішення**: `Field` приймає інтерфейс сховища через конструктор. `DatabaseModule` успадковує `AbstractModule`, зв'язує цей інтерфейс із SQLite-реалізацією та надає JDBC-з'єднання provider-методом. Точка запуску створює Injector і запитує об'єкт через `getInstance`.

**Обґрунтування**: Контракт лишає доменний клас незалежним від SQL і конкретного драйвера; модуль Guice є композиційним коренем, де обирається реалізація. Provider-метод є стандартним механізмом Guice для надання залежності, яку не створює звичайний constructor injection.

**Альтернативи**: Створення з'єднання в `Field` або статичний доступ до контейнера порушують інверсію залежностей. Ручне створення `Field` не демонструвало б обов'язковий сценарій `injector.getInstance(...)`.

**Джерела**: [Guice Getting Started](https://github.com/google/guice/wiki/GettingStarted), [Guice 7 `@Provides`](https://google.github.io/guice/api-docs/7.0.0/javadoc/com/google/inject/Provides.html).

## Рішення: JDBC-з'єднання та SQLite UPSERT за стабільним ключем

**Рішення**: Використати `sqlite-jdbc` для локального файла `target/agrofarm.db`. SQLite-сервіс створює таблицю з `operationId` як первинним ключем і виконує параметризований `INSERT ... ON CONFLICT(operationId) DO UPDATE`. Кожен запис зберігається окремо в режимі автокоміту; читання повертає всі збережені записи.

**Обґрунтування**: У SQLite UPSERT перетворює конфлікт унікального ключа на оновлення, а рішення приймається окремо для кожного рядка. Незалежний запис кожної демонстраційної операції відповідає вимозі зберегти успішні операції, якщо інша не вдалася. JDBC `Connection` за замовчуванням має автокоміт, а `close()` звільняє ресурси.

**Альтернативи**: Повне видалення таблиці перед кожним запуском знищило б дані попередніх запусків. Спільна транзакція для всіх операцій відкотила б успішні записи при помилці одного рядка. Пакетна вставка ускладнила б вимогу часткового успіху.

**Джерела**: [SQLite UPSERT](https://sqlite.org/lang_upsert.html), [Java 21 `Connection`](https://docs.oracle.com/en/java/javase/21/docs/api/java.sql/java/sql/Connection.html).

## Рішення: статичний HTML звіт із чіткою політикою помилок

**Рішення**: Після спроб збереження прочитати записи через сервіс та сформувати один статичний файл у `target`. Генератор екранує HTML-спеціальні символи для кожного значення, яке вставляється як текст. Якщо читання не вдалося, звіт не створюється; якщо не вдалося окреме збереження, створити звіт із доступних рядків і попередженням.

**Обґрунтування**: Звіт відображає фактичний стан БД, а не проміжний список у пам'яті; помітне попередження не видає частковий успіх за повний. Екранування контексту HTML гарантує текстове відображення атрибутів.

**Альтернативи**: Включати у звіт незбережені об'єкти означало б показувати дані, яких немає в БД. Приховувати помилки або формувати сторінку без успішного читання суперечило б вимогам специфікації.

## Застосування до наявного репозиторію

Наявні виробничі та тестові джерела вже лежать у стандартних Maven-каталогах `src/main/java` і `src/test/java`. Класи `Field`, `TechOperation` і точка запуску `DemoMain` лишаються в пакеті `agrofarm`; нові інфраструктурні класи розділяються на підпакети збереження та звіту. На час планування Maven 3.9.16 уже доступний у середовищі, тому встановлення Maven і зміна `PATH` не потрібні.
