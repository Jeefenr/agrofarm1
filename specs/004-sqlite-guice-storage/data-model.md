# Модель даних та відповідальностей

Модель доповнює наявні класи `agrofarm.Field` і `agrofarm.TechOperation`; вона не змінює агрегацій і композицій, визначених у `docs/class.mmd`.

## Сутності та типи

| Тип | Дані | Відповідальність і правила |
|---|---|---|
| `Field` | `fieldId`, назва, призначені операції, інтерфейс сховища | Ціле композиції та власник операцій. Приймає сховище через конструктор і викликає його для призначених операцій; не містить SQL і не залежить від SQLite. |
| `TechOperation` | Стабільний `operationId`, тип, стан, власник `Field` | Частина поля. Ідентифікатор не змінюється між демонстраційними запусками; тип і стан формують дані збереження. Операція не може належати кільком полям. |
| `OperationRecord` | `operationId`, `operationType`, `status`, `fieldId` | Не змінюваний запис/DTO для межі між доменом і сховищем та для звіту. `operationId` є ключем UPSERT; інші поля зберігаються як актуальні атрибути. |
| `TechOperationStore` | Контракт `save` і `findAll` | Доменний інтерфейс із методами предметної області; повідомляє про помилки сховища, не повертаючи успіх у разі помилки. |
| `SQLiteTechOperationStore` | JDBC `Connection` | Ініціалізує таблицю, зберігає/оновлює запис за `operationId` і читає всі рядки. Це єдиний компонент, що містить SQL. |
| `DatabaseModule` | Налаштування Guice, шлях до файлу БД | Прив'язує `TechOperationStore` до SQLite-реалізації й надає підключення до `target/agrofarm.db`. Не містить предметної логіки. |
| `FieldIdentityModule` | `fieldId`, назва поля | Надає параметри конкретного поля дочірньому Injector, не створюючи сховище чи JDBC-з'єднання. |
| `HtmlReportGenerator` | Шлях вихідного файлу | Формує `target/operations.html` зі списку прочитаних записів та, за потреби, повідомленням про помилки збереження. Екранує всі текстові значення для HTML. |
| `DemoMain` | Сценарні об'єкти, Injector, помилки запису | Зберігає наявний порядок сценаріїв, створює Injector і отримує `Field` через `getInstance`, координує збереження/читання/звіт і закриває ресурси. |

## Запис SQLite

Таблиця технічних операцій має зберігати:

| Поле запису | Тип даних (логічний) | Обмеження |
|---|---|---|
| `operation_id` | Текст | Первинний ключ, обов'язковий стабільний ідентифікатор |
| `operation_type` | Текст | Обов'язковий тип операції |
| `status` | Текст | Обов'язковий поточний стан |
| `field_id` | Текст | Обов'язковий ідентифікатор поля-власника |

Окрема таблиця для полів не потрібна: зв'язок операції з полем зберігається через `field_id`. Вставка з конфліктом первинного ключа оновлює тип, стан та ідентифікатор поля. Новий ключ додає рядок; повторний запуск із тими самими ID не створює дублікатів.

## Зв'язки та життєвий цикл

- `Field` композиційно володіє `TechOperation`; сховище не змінює це відношення.
- `Field` залежить від `TechOperationStore` через конструктор; SQL-реалізація отримується через Guice binding. Кореневий Injector володіє спільним сховищем і з'єднанням, а дочірні Injector надають кожному `Field` його ID та назву й створюють його через `getInstance(Field.class)`.
- Один запуск створює залежності, послідовно виконує наявні сценарії, викликає збереження кожної призначеної операції, читає весь результат із БД і формує HTML.
- Помилка запису окремого рядка додає повідомлення до переліку помилок, але не скасовує попередні успішні рядки і не зупиняє спроби збереження інших операцій.
- Помилка читання не дозволяє сформувати звіт. Помилки запису при успішному читанні дають звіт з фактичними рядками та явним попередженням.
- Відсутній `target` створюється до відкриття БД та запису HTML; неможливість створення є явною помилкою.
- Успішне завершення закриває JDBC-з'єднання; помилка закриття не повинна маскувати попередню помилку.

## Перевірки даних

- `operationId`, `operationType`, `status` і `fieldId` мають бути визначеними непорожніми значеннями до збереження.
- Операція призначається одному полю; у запис потрапляє ID саме цього поля.
- Повторний `operationId` оновлює відповідний рядок, не додаючи другого.
- Текстові значення у HTML показуються як текст, включно з `<`, `>`, `&`, лапками; вони не інтерпретуються браузером як розмітка.
- Порожній результат запиту показується як зрозумілий порожній стан без синтетичних рядків.
