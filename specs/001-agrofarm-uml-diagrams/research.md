# Дослідження: UML-модель агропідприємства

## Рішення: перевіряти артефакти локальними інструментами без runtime-залежностей

**Рішення**: Для `docs/usecase.puml` використовувати перевірку синтаксису PlantUML; для Mermaid-файлів — локальний рендер Mermaid CLI. Ці інструменти не є залежностями Java-застосунку.

**Обґрунтування**: Специфікація вимагає текстові PlantUML і Mermaid артефакти, але не розширює поведінку чи залежності застосунку. Успішний рендер Mermaid і перевірка PlantUML виявляють помилки синтаксису.

**Альтернативи**: Mermaid Live Editor або ручний перегляд можна використовувати замість встановлення локального CLI, але вони не дають такої ж відтворюваної локальної перевірки. Експорт зображень не включати до комплекту результатів, бо вони не вимагаються.

**Довідка**: [PlantUML command line](https://plantuml.com/command-line), [Mermaid CLI](https://github.com/mermaid-js/mermaid-cli), [Mermaid usage](https://mermaid.js.org/config/usage.html).

## Рішення: створити окремий аркуш CRC для кожного класу

**Рішення**: Розміщувати одну картку на окремому аркуші книги `docs/crc.xlsx`: назва класу як заголовок, колонки «обов'язки класу» та «з ким співпрацює». Створити дев'ять аркушів для дев'яти класів; `IWorkPlan` виключити.

**Обґрунтування**: Такий формат робить межі карток однозначними та дає змогу безпосередньо перевірити їхню кількість, заголовки та назви класів. Вимога задає CRC-картку на кожен клас, а не на інтерфейс.

**Альтернативи**: Розташувати всі картки послідовними блоками на одному аркуші. Це також можливо, однак перевірка кількості карток і структури стає менш прямою.

**Довідка**: [openpyxl tutorial](https://openpyxl.readthedocs.io/en/stable/tutorial.html) описує завантаження й читання книг XLSX для локальної перевірки.

## Рішення: валідувати книгу як XLSX та перевіряти її вміст

**Рішення**: Відкрити книгу локально сумісною бібліотекою/табличним застосунком і перевірити наявність дев'яти аркушів, назву класу та дві колонки на кожному.

**Обґрунтування**: Перевірка лише розширення файла не підтверджує, що книга читається або має потрібний склад карток. Локальна перевірка не вимагає інтеграцій чи постійної бібліотеки у Java-застосунку.

**Альтернативи**: Відкрити файл вручну в LibreOffice або Excel; це підтвердить перегляд, але гірше підходить для повторюваної перевірки кількості та заголовків.

## Рішення: не створювати зовнішні контракти

**Рішення**: Не створювати каталог `contracts/`.

**Обґрунтування**: Функція створює внутрішню документацію навчальної системи. Специфікація прямо виключає базу даних, зовнішні інтеграції та реальне підключення до погодного сервісу; публічного API або інтерфейсу інтеграції не визначено.

**Альтернативи**: Описати штучний API чи зовнішній погодний контракт — це розширило б межі функції та суперечило б FR-015.

## Вирішені невідомі

Технічних невідомих, що блокують планування, немає. Формати, шляхи, необхідні типи та сценарії задані у специфікації; фактичний Java-код і збірка не є результатом цієї функції.
