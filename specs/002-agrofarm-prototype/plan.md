# План реалізації: Імітаційний прототип агропідприємства

**Гілка**: `002-agrofarm-prototype` | **Дата**: 2026-10-30 | **Специфікація**: [spec.md](spec.md)

**Вхід**: специфікація функції у `specs/002-agrofarm-prototype/spec.md`.

## Підсумок

Створити навчальний Java-застосунок, що без взаємодії з користувачем відтворює один детермінований сезонний цикл: агроном планує культуру, механізатор завершує польову роботу, комірник обліковує врожай, а агроном переглядає аналіз. Дев'ять предметних класів та їхні зв'язки відтворюють нормативні UML-діаграми й CRC-картки. Застосунок використовує лише JDK, зберігає стан у пам'яті, моделює погодний контекст і виводить україномовні повідомлення замість реальних операцій. README містить команди компіляції, перевірки й запуску.

## Технічний контекст

**Мова/версія**: Java 21 (мінімальна версія JDK; компіляція з `--release 21`).

**Основні залежності**: Лише стандартний JDK; без бібліотек, фреймворків і системи збірки.

**Зберігання**: Дані в пам'яті лише на час запуску; база даних і постійне зберігання не використовуються.

**Тестування**: Самодостатній Java-перевіряльник без тестових залежностей; окремо перевіряються бізнес-правила та повний консольний запуск.

**Цільова платформа**: Консольне середовище з JDK 21 або новішим і POSIX-сумісною оболонкою для команд README.

**Тип проєкту**: Навчальний консольний застосунок.

**Цілі продуктивності**: Не застосовуються; один невеликий демонстраційний сезонний сценарій.

**Обмеження**: Автоматичний сценарій без меню та введення; тільки українські повідомлення користувачеві; відсутність зовнішніх побічних ефектів і мережевих викликів; програмні ідентифікатори англійською; явне передавання залежностей; UML та CRC мають відповідати коду.

**Масштаб**: Три ролі, чотири кроки сезонного сценарію, дев'ять предметних класів, інтерфейс `IWorkPlan` та перелік `FieldWorkStatus`; окремий клас запуску й один тестовий перевіряльник.

CRC лишається набором із дев'яти карток предметних класів, визначених специфікацією.

## Підхід до реалізації

1. Створити предметні класи та зв'язки згідно з `data-model.md`, зокрема успадкування ролей, композицію `Field`—`TechOperation`, перевантаження обліку врожаю й явну залежність погоди.
2. Реалізувати перевірки на рівні власника даних: польова робота змінює стан лише після перевірки обов'язкових даних; операція має належати вибраному полю; надходження перевіряється на додатність і дублікати до зміни суми.
3. Реалізувати сезонний аналіз лише за наявності облікованих надходжень, не підміняти відсутні дані нульовою урожайністю.
4. Додати `DemoMain` із фіксованими даними та послідовним викликом чотирьох сценаріїв. Відсутність модельованого прогнозу повідомляється окремо й не блокує коректну роботу.
5. Додати `PrototypeChecks` без стороннього тестового фреймворку. Перевірити переходи стану, неповні дані, погодний варіант без прогнозу, належність операції полю, відмову недодатних і повторних надходжень без зміни суми та аналіз сезону без даних.
6. Оновити кореневий README точними командами JDK 21 для компіляції, тестування та демонстрації. Синхронно відобразити точку запуску й необхідні поведінкові уточнення у діаграмах; перевірити, що дев'ять CRC-карток відповідають дев'ятьом предметним класам.
