# Перевірка вимог: Імітаційний прототип агропідприємства

**Purpose**: Оцінити повноту, ясність, узгодженість і перевірюваність вимог задачі 002.
**Created**: 2026-10-30
**Feature**: [spec.md](../spec.md)

**Note**: Цей користувацький чекліст створено командою `/speckit-checklist` на основі контексту функції.
**Review Ownership**: Чекліст належить рецензенту й оцінює якість вимог. Позначайте пункт `[x]` лише після підтвердження, що відповідний критерій якості вимог задоволений.
**Marker Semantics**: `[x]` означає, що критерій якості вимог перевірено й задоволено; це не означає завершення реалізації.

## Повнота вимог

- [ ] CHK001 — Чи пов'язують вимоги планування культури, польову роботу, облік урожаю та аналіз у повний сезонний сценарій? [Completeness, Spec §FR-001]
- [ ] CHK002 — Чи визначено ролі агронома, механізатора й комірника та їхні обов'язки у сценарії без покладання на неописані взаємодії? [Completeness, Spec §FR-002]
- [ ] CHK003 — Чи чітко окреслюють вимоги межі симуляції: відсутність реальних операцій, мережевих запитів, сторонніх ефектів і постійного зберігання? [Completeness, Spec §FR-009, Assumption]
- [ ] CHK004 — Чи перелічені всі нормативні типи, зв'язки та CRC-картки, потрібні для оцінювання повноти предметної моделі? [Completeness, Spec §FR-003, §FR-011–FR-012]

## Ясність вимог

- [ ] CHK005 — Чи визначено одиниці вимірювання та правило порівняння врожайності за полями, щоб результат аналізу можна було однозначно тлумачити? [Ambiguity, Spec §FR-007–FR-008]
- [ ] CHK006 — Чи однозначно визначено, що вважається повтором надходження: повторний ідентифікатор квитанції та повторна комбінація поля, сезону й кількості? [Clarity, Spec §FR-007]
- [ ] CHK007 — Чи зафіксовано мінімальну версію JDK і вимоги до середовища командного рядка саме як обов'язкові умови запуску? [Clarity, Spec §FR-010, Gap]
- [ ] CHK008 — Чи узгоджено формулювання про «чотири задокументовані бізнес-сценарії» з описом одного сезонного циклу та чотирьох його дій? [Ambiguity, Conflict, Spec §FR-001, §SC-002]

## Узгодженість вимог

- [ ] CHK009 — Чи узгоджуються автоматичний сценарій без введення даних і вимога розглядати негативні випадки окремо, без неоднозначності щодо того, що має демонструвати користувацький запуск? [Consistency, Spec §FR-014, §US-2]
- [ ] CHK010 — Чи відповідають критерії успіху функціональним вимогам щодо переходів стану, відхилення обліку та аналізу без даних? [Consistency, Spec §FR-005–FR-008, §SC-003–SC-004]
- [ ] CHK011 — Чи визначено однаково нормативність і межі узгодження діаграм, CRC-карток та вимог до коду? [Consistency, Spec §FR-003, §FR-011–FR-013]
- [ ] CHK012 — Чи встановлено достатню простежуваність між вимогами, сценаріями приймання, критеріями успіху та відповідними діаграмами/CRC-картками? [Traceability, Spec §FR-011, §SC-005]

## Якість критеріїв приймання

- [ ] CHK013 — Чи дають критерії приймання змогу об'єктивно розрізнити успішну операцію, відмову через некоректні/повторні дані та відсутність даних? [Measurability, Spec §FR-009, §SC-007]
- [ ] CHK014 — Чи визначено скінченний набір випадків, до якого застосовується вимога «100%» для перевірок польової роботи й надходжень? [Ambiguity, Spec §SC-003–SC-004]
- [ ] CHK015 — Чи можна за критеріями успіху однозначно оцінити правильність складу сезонного аналізу, зокрема коли врожай мають лише окремі поля? [Measurability, Spec §FR-008, §SC-004]

## Покриття сценаріїв і граничних випадків

- [ ] CHK016 — Чи повністю визначено результати для відсутніх поля, сезону або операції, недодатної кількості, повторного надходження, відсутніх даних урожаю та недоступного прогнозу? [Coverage, Edge Case, Spec §FR-005–FR-008]
- [ ] CHK017 — Чи уточнено поведінку повторного завершення роботи або повторної спроби після невдалого завершення, якщо ці переходи входять до обсягу прототипу? [Gap, Spec §FR-005, §FR-011]
- [ ] CHK018 — Чи визначено, як сезонний аналіз трактує поля без надходжень і надходження, що належать іншому сезону? [Coverage, Spec §FR-008, Edge Cases]

## Нефункціональні вимоги та припущення

- [ ] CHK019 — Чи поширюються вимоги української мови на всі повідомлення, які бачить користувач, та чи чітко відділено їх від англомовних програмних ідентифікаторів? [Completeness, Spec §FR-009, §FR-013]
- [ ] CHK020 — Чи достатньо конкретно визначено, які зовнішні ефекти заборонені, щоб вимога безпечної симуляції не мала різних тлумачень? [Clarity, Spec §FR-009, §SC-007]
- [ ] CHK021 — Чи задокументовано та підтверджено припущення про наявність JDK, нормативних UML-діаграм і CRC-карток, від яких залежить виконання та перевірка вимог? [Assumption, Dependency, Spec §FR-003, §FR-010–FR-012]
